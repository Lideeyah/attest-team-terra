# Attest production integration plan

Prepared 11 November 2026. All work stays on `mark/production`. Backend source is
`origin/raheem/backend-spec-alignment-frontend-handoff`. No frontend re-clone is needed.

## Outcome and source precedence

Connect the existing Next.js interfaces to the implemented Fastify API; replace
simulated operational behaviour with durable backend results; provide an interactive
OpenStreetMap map backed by PostGIS boundaries and privacy-preserving H3 aggregates.
Complete each feature with validation and a separate commit. Do not push or deploy
as part of the local integration unless requested.

Use the branch's `docs/frontend-integration.md`, `docs/frontend-api-reference.md`,
shared contracts and route/service code for implemented wire behaviour. The attached
Word handoff supplies product intent; its HMAC, response-shape and endpoint assumptions
must not override the newer backend. Preserve the existing brand colours and UI fixes.

## Confirmed starting conditions

- Backend is Fastify/TypeScript, not Next.js route handlers. API defaults to port 8080.
- Frontend and backend branches have no merge base. A root merge would collide with
  package manifests, scripts, public assets, TypeScript settings and documentation.
- Import the backend into `backend/`, preserving its independent build and local
  runner. Record the exact imported commit. Keep browser-safe contracts as a local
  package dependency with a reproducible clean-install/build arrangement.
- Frontend has uncommitted, user-authorised UI changes. Checkpoint these before import.
- Local backend provides persistent embedded PostgreSQL/PostGIS plus a worker, with
  mock external providers. A completed backend does not make these live bank payments.
- Local credentials are generated by its runner. Keep credentials, state and keys
  ignored and out of logs, screenshots, commits and browser bundles.

## Feature sequence and commits

### 1 Preserve frontend and import backend

Checkpoint the completed UI work in its own commit. Bring backend source into
`backend/` without replacing the frontend root. Preserve relative backend paths and
ignored local state. Add explicit root commands for backend build/start/check and
document one frontend plus one backend local startup sequence. Validate dependency
installation, contracts build, migrations/local seed, worker and `/healthz`.

Commits: `fix(ui): improve spacing navigation and record readability`, then
`build: integrate backend service and shared contracts`.

### 2 Same-origin routing and real sessions

Proxy `/api/*` and `/auth/*` to Fastify in live integration mode; exclude mock route
trees. Deliberately handle receipt HTML and evidence/PDF downloads. Forward cookies
and Set-Cookie, multipart bodies, request IDs and SSE without buffering. Server-side
reads must forward the incoming authentication context too. Keep the public callback
origin consistent; audit the local runner's hardcoded PUBLIC_URL.

Use Auth.js cookie login/CSRF/sign-out, role-aware navigation, real session identity,
project selection/context, 401 expiry and 403 refusal. No persistent browser bearer
tokens. Consolidate field/main API configuration. Remove fixed fixture clock/account
assumptions. Use retained idempotency keys per action and reconcile uncertain mutations.

Commit: `feat(auth): connect same-origin backend sessions and role access`.

### 3 Wire contracts and project onboarding

Create explicit boundary adapters between backend DTOs and existing view models;
never cast incompatible responses or invent missing financial facts. Support null
extraction results, list metadata, unknown error codes and safe friendly error copy.

Connect registry lookup, validated KML geometry/boundary IDs, project creation,
multipart PDD upload and extraction polling with backoff. Track the previous extraction
row so stale results are not accepted as new. Save commitment edits sequentially with
reasons; support staged payment metadata and reporting cadence. Show actual source
quotation/page and pending source-edition alignment. Remove unsupported KYB success.

Commit: `feat(onboarding): integrate registry boundary and commitment review`.

### 4 Roster, agent identity and field evidence

Align supported filters/status changes and per-item batch results. Upload actual photo,
consent and receipt voice evidence; use returned evidence IDs. Add required name/date
of birth/account/bank fields and NIN payout-account handling. Wire invitation redemption,
pending activation and administrator agent identity verification.

Replace HMAC with device-held Ed25519 keys and canonical signatures over exactly
capturedAt/clientId/point/projectId; export public SPKI PEM only. First prove one signed
capture against the backend. Preserve IDs/timestamps across retries. Implement encrypted
offline sensitive capture storage, acknowledgement-based deletion and explicit lost-key
behaviour; do not silently drop identity verification or persist unprotected BVN/NIN.
Do not represent unsupported device rotation as successful binding.

Commit: `feat(field): integrate signed captures evidence and roster workflows`.

### 5 Runs, settlement updates and reconciliation

Use backend reporting periods, decimal-string arithmetic, declaredNet where required,
preflight exclusions and exact run/transfer states. Execute once and observe job results;
allow only supported definitive retry classes. Requery uncertain outcomes. Use SSE
onmessage events as invalidations, coalesce refreshes and reconcile after reconnect.
Separate settled/failed/reversed/pending and household confirmation. Wire actual account
funding/reconciliation DTOs and missing-account handling. Remove fabricated payment totals.

Commit: `feat(payments): integrate preflight execution streaming and reconciliation`.

### 6 Signed records, participant channels and verifier tools

Render signed document fields and historical denominators. Keep corrections separate
without double counting. Wire public signed PDF, private report PDF/JSON, multipart PDF
verification, canonical backend disclosure bundles and anchor status. Never reproduce
the mock Merkle format instead of the backend format.

Wire token receipt confirmation/disputes/audio and generic public dispute categories.
Connect verifier comparison, watchlists, rules/events and JSON/CSV/PDF exports; download
the supplied content safely. Label monetary-coverage alerts distinctly from household
coverage. Unsupported deletion/update/API-key controls must explain availability rather
than simulate success. Preserve synthetic/reference notices in rows, charts and exports.

Commit: `feat(records): integrate signed reports receipts and verifier workflows`.

### 7 OpenStreetMap and PostGIS GIS experience

Replace the schematic BucketMap with a client-loaded interactive GIS map. Choose a
maintained map library after checking compatibility and official usage documentation.
Use OpenStreetMap basemap attribution and follow the tile provider's usage policy;
no bulk tile download or offline OSM tile prefetch. Preserve the existing brand palette
for overlays and controls.

- Render full GeoJSON Polygon/MultiPolygon boundaries, including holes; convert
  longitude/latitude order explicitly. Use backend PostGIS area, not a browser estimate.
- Convert returned H3 cell IDs into actual geographic hexagon boundaries. Respect
  resolution 4 and suppression of cells below five households; never reconstruct them.
- Provide layer toggles, readable legend/count bins, scale bar, coordinates, reset/fit
  extent, keyboard access, feature selection and informative popups with provenance.
- Handle missing geometry, empty geography, loading, tile failure and differing CRS
  assumptions explicitly. Provide an accessible summary alongside the map.
- Give authorised users boundary/enrolment-review layers only where APIs permit;
  public/verifier maps receive aggregate data only. No exact household points on OSM.
- Populate local PostGIS fixtures with deterministic, geographically coherent synthetic
  enrolments within/around labelled demonstration boundaries, sufficient for meaningful
  H3 coverage. Show outliers and suppression correctly. Do not present synthetic test
  polygons as authentic project parcels or reference populations as payment denominators.
- If required geometry/context endpoints are absent, add narrow role-scoped backend
  endpoints with disclosure tests; document every extension. Never fetch private geometry
  by bypassing a forbidden role.

Commit: `feat(maps): add OpenStreetMap boundaries and H3 enrolment analysis`.

### 8 Operations, administration and unsupported API inventory

Align signals/graphs/cases/exceptions/reconciliation with actual DTOs. Respect account
control/onward-flow capabilities and distinguish queued actions from completed bank
actions. Wire jobs, extraction proposals/review, registry import/history, project account
linking and per-project chain checks. Guard privileged actions by role.

Audit every existing client method against routes, request parsing and service rules.
Publish an inventory of connected, adapted, unsupported and externally blocked APIs,
with affected screens, required follow-up and validation evidence. Implement justified
small backend extensions only with persistence, scoping and tests; do not fabricate
full new administrative subsystems to hide omissions.

Commit: `feat(ops): integrate operations administration and capability handling`.

### 9 End-to-end verification and handback

Run frontend/backend type checks, relevant backend regression/integration tests and
frontend tests. Run existing browser gates serially, first classifying fixture-only
assumptions; a mock gate passing is not live integration proof. Add focused live checks
for auth forwarding, idempotency, signing, privacy, financial state and downloads.

Walk the local-backed journey: login, project/KML/PDD review, household capture, run
preflight/execution/SSE, reports/public verification, verifier export and operations.
Test role denial, expiry, multipart errors, mixed batch results, source-account absence,
timeout/requery, map holes/multipolygons, empty/suppressed H3 cells and narrow screens.
Scheduled closing must remain a worker responsibility, not a new public close button.

Document commands, provider modes, tested paths, known defects, API gaps and exact
commit checkpoints. No release claim without the appropriate evidence.

Commit: `test: verify integrated workflows and document remaining gaps`.

## Known gaps to resolve or report

The backend reference explicitly omits private project collection; developer KYB/tier
onboarding; developer extraction job details; approved-language discovery; device-key
rotation; watchlist removal and alert update/removal; and carbon purchase checkout.
Existing frontend console users/API keys/webhook endpoints, verifier keys, import-job
tracking and several admin queues need route-by-route audit rather than assumed support.
Field profile does not advertise the cached boundary/target shape the frontend expects;
the documented private boundary GET is developer-only. Public H3 aggregates do not
constitute a public parcel-boundary endpoint.

Other open items: account-linking authority/configuration, public callback origin,
SMTP/messaging/provider capabilities, real anchor credentials, the requested PDD source
edition and unexplained allocation remainder, rate-limit/proxy IP handling and offline
sensitive-data/key lifecycle. Report these separately from implementation bugs.

## Time budget

Target the requested 60-105 minute window as a working timebox, not a guarantee of full
acceptance. First 10 minutes: baseline/import/startup. Next 20: routing/auth/contracts.
Next 25: core onboarding/field/payments. Next 20: records/map. Final 15-30: operations,
validation and gap report. These are checkpoints, not permission to skip features or
verification. GIS, encrypted offline capture, previously missing APIs or provider/setup
failures can exceed this window; report concrete progress and remaining work honestly.
